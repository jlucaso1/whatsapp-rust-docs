## Performance

**Binary: `Jid::Display` / `JidRef::Display` reduced to a single `write_str` ([#848](https://github.com/oxidezap/whatsapp-rust/pull/848))**

`jid.to_string()` previously paid one `malloc` plus a realloc chain: `Display` wrote up to seven fragments (`user`, `.`, `agent`, `:`, `device`, `@`, `server`) into the initially-empty `String`, growing the buffer piece by piece. This ran on every `MessageKey` build, receipt, stanza attribute write, and PDO key — making it a consistent hot-path allocator.

`Display` now writes the JID into a 64-byte `[u8; 64]` stack buffer first and emits a single `write_str` to the formatter. When the JID fits in the stack buffer (the common case), a `ToString`-backed `String` calls `reserve` exactly once at the final length with no reallocation. JIDs with unusually long user parts (rare in practice) exceed the 64-byte budget and fall back to the original fragment-by-fragment path, keeping behavior identical for all inputs.

`format!` and log sites also benefit: one `write_str` into the format buffer instead of seven, while padding and width specifiers work exactly as before.

**Measured (local wall-time A/B, `bench_jid_to_string`):** median 176.7 ns → 69.7 ns (−61%).

**No breaking changes.** The `Display` output is byte-identical to before.
